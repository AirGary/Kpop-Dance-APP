# Stage Lab 保守混合 Re-ID 设计

**状态：** 用户已确认设计，等待规格审阅与实施计划

## 目标

让同一位舞者在快速移动、短时遮挡或镜头切换后能够继续被识别和跟随，同时把错误锁定另一位舞者的风险降到最低。首版只面向本地真实 AI Demo 和 iPhone 17 Pro Max（iOS 26.5）。

## 范围

包含：

- 在现有 RTMDet-m + ByteTrack 轨迹之上建立可合并的轨迹片段。
- 使用全身裁切的低分辨率颜色/纹理描述、归一化姿态比例与时序位置生成轻量身份相似度。
- 将高置信度片段自动合并；低置信度片段进入用户确认状态。
- 在确认后继续目标姿态、聚光轨迹、竖屏全身跟随和动作时间轴生成。
- 为候选聚类、身份不确定、确认恢复和完整画面回退提供自动测试与真实视频验收。

不包含：

- 新的第三方 Re-ID 神经网络、额外模型权重、云端 GPU、账号、云端上传或人脸识别。
- 变更 Analysis Package ZIP 成员、现有下载接口或 iOS 26.5 以外的适配。
- 把用户视频、候选图或外观描述提交到 Git 或用作训练数据。

## 方案

每条 ByteTrack 片段在结束时生成一个仅驻留当前 Job 工作区的 `TrackDescriptor`：

1. 全身框内部的降采样 HSV 颜色直方图和边缘密度，描述服装外观但不提取人脸。
2. RTMPose 可用时的躯干、肩宽和髋宽相对比例，以及骨架质量分数。
3. 片段首末位置、速度和时间间隔，用于排除不合理的跨画面匹配。

相似度仅在时间相邻、空间/速度合理的片段之间计算。高于自动阈值才合并；处于确认区间的片段不会自动合并；低于拒绝阈值的片段视为不同舞者。

不新增模型许可证风险。若首版的真实样本显示外观/姿态描述不足，再单独评估专用 Re-ID 模型的许可、成本和准确度，不在本任务暗中引入。

## 用户确认流程

1. 用户先从候选列表选择一位舞者身份簇。
2. 目标分析遇到确认区间时，Job 进入 `awaitingIdentityConfirmation`，停止产生之后的目标姿态和裁切轨迹。
3. App 显示断点前后两张代表图、时间范围和“是否仍是所选舞者？”。
4. 用户选择“是，同一位舞者”后，服务合并片段并从检查点继续分析。
5. 用户选择“不是”后，该片段不属于目标；该时间段的播放器回退完整画面，随后可继续等待下一段高置信度目标轨迹。
6. 用户取消或离开时，Job 保留确认状态；重新进入可继续确认，不重新上传或重新分析已完成部分。

任何无法安全确认的区间都不得显示“全身锁定”，骨架也不得跨越该区间插值。

## 数据与接口

- Worker 内部新增 `TrackFragment`、`TrackDescriptor`、`IdentityCluster` 和 `IdentityDecision`；这些是本地临时数据，不写入 Analysis Package。
- 候选接口继续返回 `candidateId`，但其语义从单条轨迹升级为一个身份簇；代表图来自簇内时间分散的片段。
- Job 状态新增 `awaitingIdentityConfirmation`，并返回确认断点的前后代表图相对路径与时间范围。
- 新增受保护的确认请求，仅接受当前 Job 的待确认 ID 与 `same` / `different` 决定；请求保持幂等并通过 compare-and-set 防止重复恢复。
- `resultReady` 的 ZIP 保持既有 manifest、pose、spotlight、timeline 和 confidence 成员不变。无法确认区间以低置信度/无聚光关键帧表达，iOS 沿用完整画面回退。

## 成本、隐私与回退

- 在现有 CPU Worker 内完成；预计只增加少量裁切和向量比较，不引入常驻服务、云费用或新模型下载。
- 原视频、候选图、描述向量和确认记录仅在受 owner/job 隔离的本地运行目录存在，并沿用现有清理规则。
- 不保存或比较人脸嵌入；不使用外部检索服务。
- 若 Re-ID 组件异常、描述无效或确认数据损坏，Job 转为可恢复失败或完整画面回退，绝不复用不可信身份。
- 可通过回退该任务的 Worker/API/iOS 提交恢复当前“每条轨迹独立候选”的行为；Analysis Package 兼容不受影响。

## 验收

- 单元测试：高相似片段合并、低相似片段拒绝、确认区间、无效描述、幂等确认、重启恢复和越权确认均有失败先行回归测试。
- Worker/API：确认前不产生跨区间姿态；“same”后从检查点恢复；“different”后对应时间段无锁定轨迹。
- iOS：确认状态能显示两张私有 Job 图片；选择后轮询恢复；不确定/不同舞者时显示完整画面状态。
- 真实 `Hype Boy` 视频：候选列表不再暴露大量碎片；所选舞者可用轨迹覆盖率目标至少 80% 的可见时长。出现不确定点必须请求确认或回退，不能错误锁定其他舞者。
- 回归：本地 AI、后端与 iOS 26.5 相关测试均通过；真实媒体、截图、绝对路径和令牌不进入 Git。
