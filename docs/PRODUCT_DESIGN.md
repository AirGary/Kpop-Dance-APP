# Stage Lab 产品设计书

> **状态：当前权威产品设计（2026-08-18 用户确认）。** 本文优先于较早的阶段规格中关于处理顺序、部署位置、固定模型组合、输出形态和验收顺序的表述。历史规格保留其已完成实现、测试证据和仍有效的安全规则，但不能覆盖本文定义的当前路线。

## 产品目标

Stage Lab 是用于 K-pop 翻跳练习的成员 Fancam 工具。用户导入多人练习视频并选择一位成员后，系统生成该成员的完整全身竖屏直拍，供镜像、变速、循环、动作观察与练习使用。

当前最高优先级不是先扩展 App 或云端能力，而是在 macOS 本机证明 AI 技术链路能够可靠实现成员 Fancam；Demo 验收后，iOS 仅适配已验证的输入、结果和交互。

## 项目两大阶段

### 阶段 1：macOS 成员 Fancam Demo（当前进行中）

在 macOS 本机以高清原片完成目标实现并验证一套组件组合确实可以生成稳定的成员 Fancam。该阶段包含组件基准、人工真值、身份融合、成片渲染和人工观看验收；不依赖 App、FastAPI、720p 分析代理、模拟器、云端或移动端性能。

完成条件是：选定成员后，成片在关键交叉、遮挡、转身和镜头移动场景中不串人，可靠帧保持头部至双脚的 9:16 构图，且低置信度只会确认或安全回退。

### 阶段 2：iOS 链路适配（阶段 1 验收后）

将阶段 1 已稳定的输入、成员选择、置信度、确认点和 Fancam 成片接入 iOS。iOS 负责导入、选择、进度、确认、播放和练习体验；不在本阶段重新选择 AI 模型或重做身份追踪。部署位置（本机、云端或移动端）由阶段 1 的准确性、耗时与成本数据决定。

## 最终产品式样

```text
导入团体练习视频
→ 识别稳定成员候选
→ 用户选择一位成员
→ 自动锁定该成员
→ 生成 9:16 全身成员 Fancam
→ 可叠加骨架、节拍与动作节点
→ 使用镜像、速度和循环完成练习
```

成员 Fancam 必须满足：

- 画面是所选成员的完整全身直拍，而不是带黄色检测框的原始视频。
- 画面可以跟随、平移和缩放，但在可靠帧中保留头部至双脚。
- 成员交叉、遮挡、转身、换位及镜头移动后不得切换到其他成员。
- 证据不足时宁可暂停请求一次确认或安全回退完整画面，不能错误锁定他人。
- 骨架、动作节点和练习控制必须对应所选成员。

## 已部署基础

| 类别 | 组件 | 职责 |
| --- | --- | --- |
| 人物检测 | RTMDet-m Person Detector | 在视频帧中定位人物框。 |
| 全身身份特征 | OpenVINO person-reidentification-retail-0277 | 将人体框编码为全身外观特征，辅助同人匹配。 |
| 姿态 | RTMPose-m COCO-WholeBody | 输出 133 个身体、脚、脸、手关键点，用于动作、质量与全身裁切。 |
| 跟踪与聚类 | 自研 ByteTrack 风格关联、外观融合、身份簇与确认状态机 | 维持短期轨迹、聚合片段并在低置信度时暂停确认。 |
| 视频处理 | FFmpeg/FFprobe | 媒体门禁、渲染和结果视频处理。 |

这些组件已经能运行，但当前五人练习室基准仍会把轨迹碎片发布为八个候选；因此不能将当前链路视为成员 Fancam 达标实现。

## 技术路线原则

### macOS-first Demo

先直接使用高清原片在 macOS 终端完成独立评估和 Fancam 渲染。此阶段不依赖 App、FastAPI、720p 分析代理、模拟器、云端或移动端性能。

只有 macOS Demo 达到验收标准后，才适配 iOS。iOS 负责导入、选择、进度、确认和播放器体验，不重新定义或猜测身份追踪算法。

### 多证据身份融合

成员身份不能依赖单一模型。最终链路以全身外观、运动轨迹、镜头运动补偿和 WholeBody 姿态为主证据；清晰正脸的人脸特征只可作为可选校准证据。

人脸特征当前未启用。启用前必须单独确认用户授权、隐私规则、模型与训练数据许可证，并采用仅本机短时内存、不上传、不写入结果包或身份档案的边界。

### 组件必须实测淘汰

不得因为模型名称、论文指标或理论上更大就直接选用。每个候选组件均需在同一高清练习视频、相同人工真值和同一 macOS 环境下比较：

- 人物检测召回；
- 成员身份准确率；
- ID switch 数；
- 遮挡恢复准确率；
- 错误锁定其他成员次数；
- 自动覆盖率、人工确认频率、处理时间和内存；
- 模型/代码/训练数据许可、哈希、CPU 可运行性和隐私风险。

当前项目的 Apache-2.0 供应链门禁继续适用。BoT-SORT 是可参考的多目标跟踪架构（运动预测、全局镜头补偿、外观融合），但其参考实现与依赖在引入前必须单独完成许可证审查；不得未经审查直接复制或部署。

## 目标架构

```text
高清原片
→ 人物检测
→ 多目标跟踪（运动预测 + 镜头补偿 + 遮挡恢复）
→ 全身 Re-ID / 人体区域属性 / WholeBody 姿态融合
→ 成员身份图谱
→ 高置信自动锁定 | 低置信人工确认 | 无证据安全回退
→ 9:16 全身 Fancam 渲染
→ iOS 练习播放器
```

## 执行阶段与门禁

### Task 1：macOS 高清基准台

建立不依赖 App 的命令行评估器，直接处理原始高清源视频，输出只含聚合指标的报告和可选临时可视化。必须能区分检测漏检、轨迹断裂、Re-ID 不足、运动关联失败和性能瓶颈。

### Task 2：人工真值与组件基准

从完整队形、交叉、遮挡、背身、快速移动和远景中抽取 30–50 个关键场景，人工标记五位成员及可见性。真值仅用于本机测试，不进入产品或云端。所有检测、Re-ID、跟踪和属性候选均以这份真值比较。

### Task 3：最终身份融合组件

仅把通过 Task 2 的检测、Re-ID 和多目标跟踪组件组成身份融合器。保持“高置信自动、低置信确认、绝不错误自动锁人”的规则。

### Task 4：macOS 成员 Fancam Demo

用户选择成员后，直接从高清原片输出可播放的 9:16 全身 Fancam MP4、置信度报告和必要的确认点。用户人工观看确认其确实像成员 Fancam 后，Demo 才算通过。

### Task 5：iOS 适配

仅在 Task 4 通过后开始。接入导入、成员选择、分析进度、低置信确认、Fancam 播放、骨架、节拍、镜像、速度与循环。部署在本地、云端或移动端的决策延后到 Demo 的准确性、耗时和成本数据齐备后。

## Demo 验收标准

- 指定五人高清基准在候选阶段得到五个稳定成员身份；不得以生产常量硬编码人数。
- 选择成员后，关键场景中不切换到其他成员。
- 遮挡或换位后能以足够证据恢复同一成员；无足够证据时请求确认或回退完整画面。
- 全身可靠帧中保留头部和双脚，输出稳定的 9:16 构图。
- 成品视频可在 macOS 本地播放，并由人工确认达到成员 Fancam 观感。
- 自动测试、真实基准和人工观看结论必须分别记录，不能互相替代。

## 非目标

- Demo 阶段不承诺实时处理、移动端本地推理或云端部署。
- Demo 阶段不启用账号、付费、训练自有模型或面部身份档案。
- 不因候选数、速度或界面进度需求降低身份安全阈值。

## 阶段 1 Task 1 实施记录

- 2026-08-18：macOS 基准 contract 已落在 `backend/workers/analysis/stage_lab_analysis/fancam_demo/`。CLI 直接读取传入高清源，检测器与全身 Re-ID 通过注入接口运行；报告只保留采样数、检测/可用特征直方图、耗时和吞吐，不写入帧、裁切、特征、标签或源路径。
- 2026-08-18：Task 1 自动测试使用合成注入 reader/detector/embedder；真实高清源与模型运行仍属于私有本机验收，不以合成测试替代真实基准。

## 阶段 1 Task 2 标注与评估协议

- 真值文件从 `docs/fancam-demo-ground-truth.template.json` 复制为本机 ignored 文件 `docs/fancam-demo-ground-truth.local.json`；文件只包含 `schemaVersion`、场景时间戳和匿名 `visibleMemberIds`，禁止源路径、帧、截图、embedding、姓名或凭据。
- 真值必须包含 30–50 个严格递增时间戳场景。场景应覆盖完整队形、成员交叉、遮挡、背身/转身、快速移动和远景构图；匿名 ID 只用于本机一致性，不代表真实身份档案。
- 评估输出只允许聚合 `detectionRecall`、`identityAccuracy`、`idSwitches`、`falseLocks` 和 `confirmationRequests`；标签与观察明细不得写入报告、结果包或云端。
- 缺失观察按未检测处理；错误身份计为 false lock；证据不足的确认请求只计数，不自动合并身份。Task 2 评估结果不能替代后续人工真值复核或 Fancam 观看验收。

## 阶段 1 Task 3 组件选择门禁

- 候选组件必须先具备已审查供应链、Apache-2.0 许可、可复验 CPU probe 和匿名本地真值的聚合评估结果，才能进入成员 Fancam 链路。
- 选择条件固定为：false lock 为零，检测召回和身份准确率均不低于 0.95，每标注分钟确认请求不超过一次。缺少真值、CPU 证据、供应链审查或任一指标时，结果必须为 `no_safe_candidate`。
- 当前仅注册 RTMDet-m + OpenVINO 0277 + 既有 tracker baseline；Task 3 不下载、替换或启用其他模型。组件 scorecard 不记录私有源、图像、向量、标签或观察明细。
